# feiq-glm · 局域网文件互传

一个**零依赖**的局域网文件/文件夹互传 Web 应用，类似飞秋 / LocalSend 的网页版。
Mac 与 Windows 11 运行同一份代码，启动后自动发现同一局域网内的其他节点，在浏览器里拖拽即可把文件"推"到对方电脑上。

## 功能

- 🔍 **自动发现**：UDP 广播自动发现同网段节点（精确按 CIDR 计算广播地址，兼容热点 /28、办公室 /23 等网段）
- 📡 **扫描网段兜底**：广播被防火墙 / VPN 拦截时，可点「扫描」用 TCP+HTTP 探测本机所有网段找节点，启动后 12 秒仍无节点也会自动扫一次
- ✍️ **手动添加**：直接输入对方 `IP:端口` 添加
- 📂 **文件 / 文件夹互传**：支持多文件与整个文件夹，自动保留目录结构
- ✋ **手动确认接收**：对方发来文件时弹窗确认，接受后才开始传输
- 📊 **实时进度**：收发双端都有进度条与状态显示
- 💬 **文本消息**：节点之间可互发简短文字
- 🛠 **零依赖**：仅使用 Node.js 内置模块，无需 `npm install`

## 环境要求

- [Node.js](https://nodejs.org/) ≥ 16（Mac 与 Windows 都需要）
- 两台电脑处于同一局域网（同一网段）

## 启动

### macOS

```bash
# 方式一：双击 start.command（首次可在"系统设置 → 隐私与安全性"中放行）
# 方式二：终端运行
cd feiq-glm
node server.js
```

### Windows 11

```bat
:: 方式一：双击 start.bat
:: 方式二：命令行运行
cd feiq-glm
node server.js
```

启动后会打印本机的局域网访问地址（如 `http://192.168.1.5:3210`）并自动打开浏览器。
**两台电脑都启动后**，双方会出现在彼此的「局域网节点」列表里。

### 防火墙放行

- **macOS**：首次运行如弹出"是否允许 node 接收传入网络连接"，点「允许」
- **Windows**：首次运行如弹出 Windows 防火墙提示，勾选**「专用网络」**后点「允许访问」

## 使用

1. 在左侧节点列表点击要发送到的设备（在线状态为绿点）
2. 把**文件或文件夹**拖入发送区，或点「选择文件 / 选择文件夹」
3. 对方网页会弹出确认框，点「接受」后开始传输，进度实时可见
4. 接受时可**修改保存路径**（默认预填上次使用的路径）；勾选「记住此路径，以后不再询问」或在 `config.json` 中设置 `"saveDirFixed": true` 后，后续接收直接存入固定目录、不再询问
5. 接收的文件按 `保存路径/<发送者名>-<时间>/` 目录存放，完成后界面会显示具体位置
6. 下方输入框可与对方互发文本消息

> 提示：只在一台电脑上运行也可以——其他设备直接用浏览器打开 `http://<该机IP>:3210`，即可互传文件（经该机中转）。

## 配置

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `PORT` | HTTP 端口（被占用自动 +1） | `3210` |
| `UDP_PORT` | 发现协议起始 UDP 端口（共尝试 5 个） | `32101` |
| `NAME` | 本机设备名 | `主机名 (系统)` |
| `SAVE_DIR` | 接收文件保存目录 | `~/Downloads/feiq-glm` |
| `CONFIG_PATH` | 配置文件路径 | `./config.json` |
| `NO_OPEN` | 设为 `1` 不自动打开浏览器 | — |

设备名和保存目录也可直接在网页上修改（保存到 `config.json`）。

> **接收路径的三种模式**：
> - **默认（询问模式）**：每次接受文件时弹窗内可修改保存路径，预填上次使用的路径（`lastSaveDir`）
> - **勾选「记住此路径」**：当前路径成为固定目录，之后接收不再询问
> - **手动固定**：在 `config.json` 中设置 `"saveDirFixed": true` 和 `"saveDir": "D:\\接收"`（或设 `SAVE_DIR` 环境变量），效果相同；想恢复询问，把 `saveDirFixed` 改回 `false` 即可

> **关于 config.json 里的 id**：id 格式为 `<本机IP>-<uuid>`。每次启动都会校验其中的 IP 与本机当前 IP 是否一致，不一致（例如把整个文件夹拷贝到了另一台电脑）会自动改写为本机 IP，因此**整份拷贝文件夹不会造成局域网 id 冲突**。若两台机器仍在运行中撞上相同 id（旧版本拷贝等历史遗留），运行期还会自动检测并重新生成。注意：本机 IP 变化（换网络）后重启，节点 id 也会随之更新，对端会将其视为一个新节点。

## 故障排查

看不到节点时，按以下顺序排查：

0. **是否整份拷贝过项目文件夹（含 config.json）？** v1.2.0 起 id 内嵌本机 IP，启动时自动改写为当前机器的 IP，拷贝文件夹不会再造成冲突；v1.1.2+ 运行中检测到同 id 节点也会自动重生 id 自愈。更早版本请删除其中一方的 `config.json` 后重启。
1. **防火墙（最常见原因）**
   - **Windows**：首次运行弹出"Windows 安全中心警报"时，必须勾选**「专用网络」**再点「允许访问」。如果当时点了取消，到 `控制面板 → 允许应用通过 Windows 防火墙` 中为 Node 勾选"专用"列；或直接运行 `start.bat` 重新触发。
   - **macOS**：首次运行如弹出"是否允许 node 接收传入网络连接"，点「允许」。若之前拒绝了，到 `系统设置 → 网络 → 防火墙` 中将 node 设为"允许传入连接"。
2. **点「扫描」按钮**：UDP 广播被拦截时，扫描用 TCP/HTTP 逐个探测网段，通常能直接找到节点（注意：两侧都要放行 HTTP 端口，扫描才有效）。
3. **手动添加**：在节点 A 的网页上输入对方 `IP:端口`（IP 用 `ipconfig`（Win）或 `ifconfig | grep inet`（Mac）查询）。
4. **代理 / VPN**：Mac 上开启 Clash、Surge 等带 TUN/增强模式的代理会吞掉 UDP 广播（本机出现 `198.18.x.x` 网卡即是），发现不了节点时先关闭再试，或直接用「扫描 / 手动添加」。
5. **路由器 AP 隔离**：部分 Wi-Fi（尤其访客网络、公司网络）开启"客户端隔离"，会阻断设备互访——任何方式都连不通。改用手机热点、网线直连或换网络。
6. **确认服务在跑**：在对方电脑浏览器里打开 `http://127.0.0.1:3210`，能看到界面说明服务正常。

| 问题 | 处理办法 |
|---|---|
| 看不到对方节点 | 按上面 1→6 逐项排查 |
| 端口被占用 | 启动日志会显示实际端口，或用 `PORT=8080 node server.js` 指定 |
| 接收目录想换位置 | 网页左上角只改名字；目录用 `SAVE_DIR` 环境变量或直接编辑 `config.json` |
| 想看发现过程 | 启动日志会打印广播目标、新节点上线、扫描结果 |

## 安全说明

本应用面向**可信局域网**（家庭 / 办公室）设计，节点间通信未做加密与鉴权，请勿在公共网络中使用。

## 实现说明

- 服务端：Node.js 内置模块（`http` / `fs` / `dgram` / `os` / `crypto`），单文件 `server.js`
- 前端：原生 HTML / CSS / JS 单页，通过 SSE 实时接收节点上下线、传输请求、进度与消息
- 传输路径：发送方浏览器 **直连** 接收方服务端（不经第三方中转）
- 同一台机器运行多个实例做测试时，请为每个实例指定不同的 `CONFIG_PATH` 与 `PORT`；若多份文件夹是相互拷贝出来的（id 相同），删掉多余副本的 `config.json` 让它重新生成
